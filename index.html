01

The decision

Imagine I'm the PM for the AI gateway. Thousands of analysts and business users just got model access. What default per-user monthly spend cap should a new workspace come with?

Customer problem

A platform admin at a 2,000-person company wants everyone to try AI models. But she owns the bill. One busy agent builder can spend more than 500 casual users put together, and finance will ask her about any surprise at month end.

📌 board: admins & budgets

Proposed change

Every workspace that turns on consumer access gets a default per-user monthly cap (one number, editable). When a user reaches it, they get a friendly "ask your admin" card instead of an error.

The question is which number to ship as the default.

Success metric

Monthly active AI users per entitled user (adoption), measured while the org's P90 monthly bill stays inside the admin's budget.

📌 north star: people using it, not dollars spent

Guardrails

Users who hit the cap in a month≤ 3%
Power users (agent builders) capped≤ 25%
Chance monthly bill tops budget≤ 10%
Cap-related admin tickets≤ 1 per 100 users

Stakeholders

  • Workspace & account admins (own the bill)
  • Business users and analysts (want answers)
  • Agent builders (heavy, spiky usage)
  • Finance / FinOps, Support, Gateway eng
  • Model partners (traffic forecasts)

Why it's hard

Usage isn't one bell curve. It's a mixture of very different people. Set the cap from the average and you'll block the builders you most want to keep. Set it from the max and the bill has no ceiling.

04

The math, from my Monte Carlo course

Chapter 5: composition. Build a hard distribution out of simple pieces you already know how to sample.

1 · Mixture: pick a persona, then sample

"Monthly spend of a random user" has no tidy formula. But it is easy to describe as a two-step story: first roll which kind of user this is (casual, regular, builder) using the persona weights, then draw that persona's spend. Doing the steps in that order gives exact draws from the messy combined distribution.

f(x) = Σ wₖ fₖ(x) 1. pick k with prob wₖ 2. draw x ~ fₖ

2 · Box-Muller: normals from two uniforms

Every persona's spend is lognormal: exp of a normal. To get the normal, take two uniforms U₁, U₂, turn them into a random radius and a random angle, and read off the x-coordinate. Then the spend is median × eσZ, so a long right tail shows up on its own.

Z = √(−2 ln U₁) · cos(2π U₂) spend = median · exp(σ Z)

3 · Convolution: the bill is a sum

The org bill is the sum of 2,000 capped spends. The exact distribution of that sum is a 2,000-fold convolution, which nobody wants to compute by hand. Simulating it is simple: draw everyone, cap, add, and repeat for 300 months. A shared "busy month" multiplier keeps months realistically correlated.

Bill_m = shock_m · Σᵢ min(spendᵢ, cap)

Why a PM should care

The average user spends about $5, but the builder persona's tail pulls the bill around. A mixture makes the tension visible: one number has to protect the budget and keep the 10% of users who create most of the value. The sweep table shows the whole trade-off curve in one glance.

05

How I'd run it on real data

Table names are illustrative. Fit the persona mixture from last quarter's usage, then replay the sweep.

SQL: monthly spend per user

-- illustrative tables
WITH monthly AS (
  SELECT user_id,
         date_trunc('MONTH', usage_date) AS month,
         SUM(tokens_in + tokens_out) AS tokens,
         SUM(list_cost_usd)          AS spend
  FROM   ai_ops.gateway.request_log
  WHERE  entitlement = 'consumer'
  GROUP BY ALL
)
SELECT month,
       percentile(spend, array(0.5, 0.9, 0.99)) AS p50_p90_p99,
       avg(CASE WHEN spend >= 40 THEN 1 ELSE 0 END) AS share_would_hit_40
FROM   monthly
GROUP BY month ORDER BY month;

Python: fit the mixture, sweep caps

import numpy as np
from sklearn.mixture import GaussianMixture

df = spark.table("ai_ops.finops.user_month_spend").toPandas()
logx = np.log(df.spend.clip(lower=0.01)).values.reshape(-1, 1)
gm = GaussianMixture(3, random_state=7).fit(logx)   # 3 personas

rng = np.random.default_rng(2026)
def bills(cap, users=2000, months=300):
    k = rng.choice(3, size=users, p=gm.weights_)       # mixture
    mu = gm.means_.ravel()[k]; sd = np.sqrt(gm.covariances_.ravel()[k])
    z = rng.standard_normal((months, users))
    shock = np.exp(0.15 * rng.standard_normal((months, 1)))
    spend = np.exp(mu + sd * z) * shock
    return np.minimum(spend, cap).sum(axis=1)       # convolution

for cap in [10, 25, 40, 60, 100]:
    b = bills(cap); print(cap, np.percentile(b, 90).round())
